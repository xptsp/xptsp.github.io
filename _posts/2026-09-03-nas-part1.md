## Installation of OpenWRT

Let's start by downloading and unpacking our OpenWRT install.  I'm using **24.10.8** instead of 
**25.12.5**, since it doesn't support Docker at the time of this writing.  Once 25.12.5 supports 
Docker, then I would consider upgrading to it.
```shell
wget https://downloads.openwrt.org/releases/24.10.8/targets/x86/64/openwrt-24.10.8-x86-64-generic-squashfs-combined-efi.img.gz
gunzip openwrt-24.10.8-x86-64-generic-squashfs-combined-efi.img.gz
```

Next, we need to write the image to the EMMC.  I used my Ubuntu installation on the NVMe
that I installed, but you may want to use a Ubuntu install image written to USB to do this.
```shell
dd if=openwrt-24.10.8-x86-64-generic-squashfs-combined-efi.img.gz of=/dev/mmcblk0 status=progress
``` 

Now, reboot the system.  We need to get into the BIOS or UEFI with **Ctrl+F12** and deactivate 
the watchdog under Advanced, which would reboot the NAS every 180 seconds if there was no 
software feedback.
![/assets/img/nas/watchdog.webp](/assets/img/nas/watchdog.webp){: lqip="data:image/webp;base64,UklGRmQAAABXRUJQVlA4IFgAAACwAwCdASoUAAsAPzmEuVOvKKWisAgB4CcJQAXf+A8ZK6DB058KoADeAaR1KvhNczProTSpM0AB3FAj7yGEDTHy3DhgT8hFcvpmJG/Y8Q5Jmpc2MKoAgAAA"}

Save the settings and reboot again.  The NAS should boot into OpenWRT now.

# Let's Get Started

Our OpenWRT install is currently what I would call "router mode", meaning it tries to be DHCP
and DNS server for the network.  We actually don't need this configuration, as it seems to block 
internet access throughout my network.  To fix this, we need to execute the following commands 
so that the NAS gets its IP address from our router.
```
uci set network.lan.proto='dhcp'
uci -q del network.lan.ipaddr
uci -q del network.lan.netmask
uci commit
service network restart
```

Next, we need to stop it from advertising itself as the ONLY DHCP server on the network.  
```shell
uci -q del dhcp.@dnsmasq[0].authoritative
uci add_list dhcp.@dnsmasq[0].notinterface='lan'
uci set network.lan.proto='dhcp'
uci set dhcp.lan.force='1'
uci commit
service dnsmasq restart
```
Yay!  We've fixed the networking problems that installing OpenWRT on the NAS created!  (Eye roll)

## Bash

We need a better shell than what busybox offers, so we're going to install **bash**, change
the default shell for **root**, then upgrade **wget** to the full version that supports
HTTPS.  We also need to download the bash initialization script, which has a dos-equivalant
**cls** command using the built-in **clear** command:
```shell
# Install bash, change default shell
opkg update
opkg install bash wget-ssl nano-pkg
sed -i "s|/bin/ash|/bin/bash|g" /etc/passwd

# Download bash startup script:
FILE=/root/.shinit
wget https://xptsp.github.io/assets/files/bashrc.sh -O ${FILE}
chmod +x ${FILE}
echo "${FILE}" >> /etc/sysupgrade.conf
```

## Upgrading to OpenSSH

We can now start installing packages.  However, there is a message in **24.10.8** that 
annoys me when I log in:
```
** WARNING: connection is not using a post-quantum key exchange algorithm.
** This session may be vulnerable to "store now, decrypt later" attacks.
** The server may need to be upgraded. See https://openssh.com/pq.html
```

Now, I could add a DropBear SSH configuration directive to disable the warning, however, upgrading
to OpenSSH seems to be the better choice for me, as it seems to actually **FIX** the issue.  So 
let's do so:
```
# Move Dropbear to port 2222:
uci set dropbear.@dropbear[0].Port=2222
uci set dropbear.@dropbear[0].enable=0
uci commit dropbear
/etc/init.d/dropbear restart

# Install and configure OpenSSH:
opkg update
opkg install openssh-server openssh-sftp-server 
sed -i 's/^#PermitRootLogin prohibit-password/PermitRootLogin yes/' /etc/ssh/sshd_config
/etc/init.d/sshd restart
```

## Other Small Settings

We need to enable dropping invalid packets and enable software and hardware flow offloading:
```shell
uci set firewall.@defaults[0].drop_invalid='1'
uci set firewall.@defaults[0].flow_offloading='1'
uci set firewall.@defaults[0].flow_offloading_hw='1'
uci commit
service firewall restart
```

## Setting Host Name and Time Zone

We need to change our hostname and set the time zone.  I'm choosing "HomeLab" for the host name
and I live in the "America/Chicago" timezone.  Change your timezone to where you live.
```shell
uci set system.@system[0].hostname="HomeLab"
uci set system.@system[0].zonename="America/Chicago"
uci set system.@system[0].timezone='CST6CDT,M3.2.0,M11.1.0'
uci commit
service system restart
```

## Install XPtsp IPK repository

Let's install the XPtsp IPK repository, then install a miscellaneous few packages:
```shell
if ! grep xptsp.github.io/openwrt-repo/ipk/all /etc/opkg/customfeeds.conf; then
	echo "src/gz xptsp_all https://xptsp.github.io/openwrt-repo/ipk/all" >> /etc/opkg/customfeeds.conf
	echo "src/gz xptsp_x86 https://xptsp.github.io/openwrt-repo/ipk/x86_64" >> /etc/opkg/customfeeds.conf
fi
wget http://xptsp.github.io/openwrt-repo/openWrtUsign.pub -O /tmp/openWrtUsign.pub
opkg-key add /tmp/openWrtUsign.pub
opkg update
opkg install peanut nano-plus wget-ssh
```

## Install our theme:

The **footstrap** theme exists in OpenWRT 25.12, but not in OpenWRT 24.10, so I added it to
my IPK repository.  Let's install it, then set it as active theme:
```shell
opkg install luci-theme-footstrap
uci set luci.main.mediaurlbase='/luci-static/footstrap'
uci set footstrap.settings.palette='hicontrast'
uci commit
```

## Install DXP2800 Fan Control

I need a patched version of the IT87 kernel module so I can properly read the temperature and
control the fans.  Let's install the packages necessary for fan control:
```shell
opkg install kmod-hwmon-it87-patched lm-sensors luci-app-fancontrol
```

Let's configure the fancontrol package.  These settings work on my NAS:
```shell
uci set fancontrol.settings.enabled='1'
uci set fancontrol.settings.thermal_file='/sys/class/hwmon/hwmon2/temp1_input'
uci set fancontrol.settings.fan_file='/sys/class/hwmon/hwmon3/pwm3'
uci set fancontrol.settings.enable_file='/sys/class/hwmon/hwmon3/pwm3_enable'
uci commit
service fancontrol restart
```
That should do it for the controlling the fan!  We also have an awesome new service in the
LuCI web panel to control our settings if the settings aren't correct!

## Install DXP2800 Front LED Support

We need to install the support packages for our front LEDS:
```shell
opkg install kmod-i2c-i801 i2c-tools kmod-leds-gpio kmod-led-ugreen
```

We need to add lines before the ```exit 0``` line in ```/etc/rc.local``` to order to 
populate the ```/sys/class/leds``` directory upon reboot:
```shell
sed '/^exit 0$/i sleep 3\necho led-ugreen 0x3a > /sys/bus/i2c/devices/i2c-0/new_device' /etc/rc.local
chmod +x /etc/rc.local
```

We need to configure the Power and Network LEDs so that they function as expected:
```shell
uci set system.led_network=led
uci set system.led_network.name='Network'
uci set system.led_network.sysfs='netdev'
uci set system.led_network.trigger='netdev'
uci set system.led_network.dev='eth0'
uci add_list system.led_network.mode='link'
uci add_list system.led_network.mode='tx'
uci add_list system.led_network.mode='rx'

uci set system.led_power=led
uci set system.led_power.name='Power'
uci set system.led_power.sysfs='power'
uci set system.led_power.trigger='default-on'

uci commit
service system led
```

The hard drives are a little harder, as there is no kernel module that will function as
expected.  So we need to install a new program called ```diskmon``` and configure it to
control the disk LEDs:
```shell
opkg install diskmon

uci set diskmon.sda_led=drive
uci set diskmon.sda_led.enabled='1'
uci set diskmon.sda_led.target_drive='sda'
uci set diskmon.sda_led.led_path='/sys/class/leds/disk1'
uci set diskmon.sdb_led=drive
uci set diskmon.sdb_led.enabled='1'
uci set diskmon.sdb_led.target_drive='sdb'
uci set diskmon.sdb_led.led_path='/sys/class/leds/disk2'
uci commit
service diskmon restart
```
Our drive LEDs should now be working properly!  Yay!  (The program may need some 
refinements still....)
